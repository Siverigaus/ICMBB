# Анализ сетей взаимодействий аминокислотных остатков NaPi2b

Пакетный анализ траекторий NAMD (PSF/DCD): построение белковых сетей взаимодействий остатков (RIN), расчёт центральностей, выделение хабов и контроль качества.

Каждая траектория анализируется отдельно. Узлы сети соответствуют аминокислотным остаткам, рёбра — взаимодействиям между ними. Липиды, гликаны и другие небелковые компоненты в сети не включаются.

## Файлы

- `NAMD_Protein_RIN_Centrality_Batch_Analysis.ipynb` — основной ноутбук анализа.
- `systems_batch2.csv` — реестр систем второй серии с метаданными и удалёнными путями к PSF/DCD.
- `summary_all_systems.csv` — метрики центральности и признаки хабов для остатков.
- `summary_all_hubs.csv` — консенсусные хабы, выделенные по пересечению критериев degree и betweenness.
- `summary_all_edges.csv` — взаимодействия между остатками, их типы, частоты и характеристики расстояний.
- `summary_system_qc.csv` — параметры анализа, характеристики графов, статусы обработки и сведения об ошибках.
- `batch1_networks.png` — визуализация сетей первой серии.
- `batch2_networks.png` — визуализация сетей второй серии.

## Иллюстрации

### Первая серия: число дисульфидных связей

`batch1_networks.png` содержит отдельные панели для трёх систем:

- `0SS` — без дисульфидных связей;
- `1SS` — со связью C303–C350;
- `2SS` — со связями C303–C350 и C322–C328.

Размер узлов соответствует degree, цвет — нормированной взвешенной betweenness. Чёрная обводка обозначает консенсусные хабы. Подписаны выбранные остатки; линии-указатели связывают подписи с узлами.

Расположение узлов основано на проекции координат Cα опорного кадра. При этом рёбра и центральности характеризуют консенсусную сеть по анализируемым кадрам траектории, а не только этот кадр.

### Вторая серия: варианты аминокислотных замен

`batch2_networks.png` предназначен для сравнения сетей успешно обработанных систем второй серии в отдельных панелях. Системы с неуспешным расчётом исключаются по статусу `failed`.

При отсутствии сохранённых координат Cα используется топологическая раскладка: положение узлов отражает структуру связей графа, а не геометрию белка. Общая раскладка служит только для сопоставления панелей; сети отдельных систем не объединяются для расчёта центральностей.

## Запуск анализа

1. Подготовьте таблицу систем с колонками `system_id`, `batch`, `length_ns`, `psf_path`, `dcd_path`.
2. В `psf_path` и `dcd_path` укажите локальные пути к соответствующим файлам. Удалённые пути из `systems_batch2.csv` необходимо предварительно преобразовать в локальные после скачивания.
3. Укажите таблицу в `SYSTEMS_CSV`, выберите группы в `RUN_BATCHES` и проверьте параметры анализа.
4. Последовательно выполните ячейки ноутбука.

Основные зависимости: Python, MDAnalysis, NetworkX, pandas, NumPy и tqdm. Для визуализации используются Matplotlib и adjustText.

## Результаты и ограничения

Результаты сохраняются в папку, указанную в `RESULTS_DIR`: отдельные таблицы для каждой системы и общие CSV-файлы.

Перед интерпретацией проверьте **качество** данных:

- соответствие состава и порядка атомов PSF и DCD;
- целостность белка через периодические границы — исходный ноутбук не исправляет разрывы автоматически;
- корректность сопоставления остатков между системами;
- версию алгоритма, использованную для расчёта частот контактов и центральностей. [colab.research.google](https://colab.research.google.com/drive/1jM3nl8OONQi1c-NpxRS6Q9wFx1uDwU1i)

Если `contactfreq` интерпретируется как доля кадров с контактом, значения должны находиться в диапазоне 0–1. Результаты с превышением этого диапазона требуют проверки подсчёта: несколько атомных контактов одной пары остатков в одном кадре не должны учитываться как несколько контактных кадров.

Добавление или изменение иллюстраций само по себе не означает пересчёта опубликованных CSV. Визуализация сохранённых центральностей не исправляет возможные ошибки исходного анализа.
